## ARM-001: ARMv7 binaries must match libc, and installation must be verified by execution

- Scope: binary selection, installation, and releases; songloft-org/songloft#544. Baseline `4ccac5d7aecce0ead2c3384afbefe8bb6c2f1b41`.
- Evidence: on 2026-10-28, the issue reported `no such file or directory` on Alpine 3.24 / armv7l even after executable permissions were fixed. The host reports Go `GOOS-GOARCH`, or `linux-arm`; the old plugin had no matching entry. Upstream `2026.10.26` provides a glibc ARMv7 directory archive, without a musl ARMv7 single-file executable. The old installer also swallowed version execution errors and reported success.
- Rule: match both architecture and libc; chmod cannot repair a missing dynamic loader. Bundle Python with the upstream PyInstaller entry point on ARMv7 Alpine, then execute in a clean musl container without Python. Installation and upload require a successful `--version`; file existence is insufficient.
- Prerelease selection: GitHub `releases/latest` excludes prereleases. Publish the custom binary and plugin in one Release, query `releases/tags/v<version>` using the installed plugin version, and keep the manual fallback on the same tag. Prereleases must not update the root stable manifests. As requested, a separate workflow appends ARM assets asynchronously without blocking plugin publishing, with an explicit not-ready message.
- Done right: Node 22.17.1 / Linux amd64; platform regressions, type checking, QuickJS packaging, manifest validation, and actionlint v1.7.12 passed. The initial ten tests failed five cases against an isolated copy of the old `binary.ts`, covering the missing ARM mapping, incorrect fallback, and false upload success. Log: `/tmp/songloft-544-armv7/negative.log`. Binary runtime evidence is recorded by the separate CI and Release build metadata; versioning and asynchronous status tests join the same checks.
- Not run: physical OneCloud hardware, authenticated sites or real user playlists, and a YouTube JS runtime. QEMU and container checks do not replace those checks.
- CI fixture: the first [independent build](https://github.com/hanxi/songloft-plugin-ytdlp/actions/runs/40628366392) produced an ARM ELF, musl interpreter, and correct version, but the uid=1000 check failed with `Permission denied` after export to the host. The [successful rerun](https://github.com/hanxi/songloft-plugin-ytdlp/actions/runs/40630315530) confirmed directory mode 0700 and executable mode 0755. Normalize both to 0755 before testing, while retaining the non-root and no-Python checks. Workflow code `5c4edf5cc2b356f6c8509afba3b24c708faa283a` passed version (2.40 seconds), extractors, actual HTTP download, and HTTPS extraction on QEMU ARMv7 / Alpine 3.24 / uid=1000. Assets were appended to `v2026.10.28.0`. Failed runtime checks preserve a diagnostic artifact without publishing it to the Release.
- Release acceptance: eighteen tests and a four-part packaging rehearsal passed; SHA-256 checks passed for the plugin package and every ARM asset. The actual package completed download, chmod, execution, and status readback through a separate Go host's real QuickJS/command bridge, with an identical installed hash. Environment: ARMv7 Alpine userland + QEMU, a static amd64 Go host, and `server_platform=linux-arm` overridden in a temporary database. Direct GitHub download on this slow network hit the host's existing 120-second timeout, so the successful installation used the existing GitHub proxy setting and a local proxy fixture serving the same verified asset. This does not constitute ARM Go host, direct-network, or physical-device acceptance. Evidence: `/tmp/songloft-544-armv7/integration-{initial,pending,ready}.json`, `retry-ci.log`, and `published/`.
- Seen 1× (2026-10-28).

## BATCH-001: Cancellation must wake waits and preserve the current call result

- Scope: batch downloads, songloft-org/songloft#544; baseline `10717798e8131c144ae10315f6b709bd635df982`.
- Evidence: on 2026-11-02 the reporter could pause but could not cancel. Clearing discarded the pause callback, while the asynchronous loop used global task state that a later batch could replace.
- Rule: hold state per batch; wake pause, interval and retry waits on cancellation. Keep the execution slot until the host's current track call settles; do not claim immediate interruption.
- Done right: 9 new regressions failed on the old implementation; all 31 final tests, type checking, QuickJS build and validation passed. Docker Chrome exercised the isolated real host: cancellation in flight, cancellation after automatic pause, clearing and a new batch. SQLite confirmed the current track became local and the queued track stayed remote. Evidence: `/tmp/songloft-544-cancel/`. The initial 4-second audio fixture hit the existing 30-second validation minimum; final checks used 40-second generated audio and a controlled resolver.
- Not run: physical OneCloud, ARMv7 execution in this run, or real third-party sites. Not committed, pushed or published.
- Seen 1× (2026-11-02).

## BIN-001: Linux binary selection must check the host's libc

- Scope: yt-dlp installation and diagnostics on Linux x86-64 and ARM64. [hanxi/songloft-plugin-ytdlp#9](https://github.com/hanxi/songloft-plugin-ytdlp/issues/9), plugin baseline `85687d23e90a34784bdcca4012cda1d1135f5eea`.
- Evidence: release `v2026.10.28.0` hit `fork/exec … no such file or directory` with the upstream musl binary present on Debian 12 x86-64. Settings showed it as installed with a blank version. The ELF requested `/lib/ld-musl-x86_64.so.1`, which the host lacked. Running the glibc binary on Alpine 3.24.1 also reproduced a missing loader. The reporter's device and binary origin remain unverified.
- Example: run `getconf GNU_LIBC_VERSION` on the Songloft server to identify glibc. Share asset selection between automatic installation and the manual download link. Base the settings status on a successful `--version` and display the ELF loader path when the host reports it missing.
- Verification: seven regressions failed against the old source. The fix passed all 40 tests, type checking, QuickJS build, and validation. Docker Chrome clicked **Reinstall yt-dlp** on a real local Songloft host. A local proxy fixture served the SHA-256-verified upstream glibc asset, and the host reported version `2026.10.26` with a matching file hash. The upstream musl asset reported the same version as a non-root user on Alpine. Live Bilibili search for “单车” returned HTTP 412 on an early attempt. A later check found five results and verified all five in a temporary playlist after import.
- Seen 1× (2026-11-22).
